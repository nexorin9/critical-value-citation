# 院内材料投递规范（阈值表 · 报告制度）

> 这份规范给**检验科 / 医务科**的出材料的人：本院危急值阈值表 xlsx 和危急值报告制度
> docx / pdf 该怎么写，系统才能认；写错了会怎样；交材料前怎么自检。
>
> **本文件的字段与别名表由 `critval/kb/schema.py` 生成，与代码同源** —— 别名表改了就重新
> 生成本文，别手改本文里的列名。

---

## 0. 一句话说清

| 材料 | 干什么用 | 交不进来会怎样 |
|------|---------|--------------|
| 阈值表 xlsx | **判定的唯一权威**：哪些结果算危急、算到哪一档 | 判不了危急值（`rules-summary` 会有缺口条数） |
| 报告制度 docx / pdf | **召回的依据**：通知谁、多久内上报、记录交回哪 | 处置卡缺依据，出卡时标注「依据缺失」 |

两份材料都是**行级可追溯**的：处置卡上写的「命中阈值表第 12 行 / 制度第 5 条 / 版本 v2.1」
必须能在文件里对上，所以材料别合并成一张大表、别把版本写在文件名里（版本写在表里）。

## 1. 阈值表 xlsx

### 1.1 表结构

| 项 | 要求 |
|----|------|
| 文件格式 | `.xlsx`（不支持 `.xls`、`.csv`） |
| 工作表 | 读**第一个**工作表；其余工作表不参与判定 |
| 表头位置 | 前 **5 行**内必须有表头（表头行上面有标题行没问题） |
| 一行一项目 | 一个检验项目一行；不要合并单元格（合并单元格会被列进解析报告待人工确认） |
| 列顺序 | 随意，按下面 1.2 的规范字段名写表头即可 |
| 字符编码 | xlsx 自带 UTF-8，不需要处理编码 |

### 1.2 规范字段与别名

表头**写成下面任一别名都能认**（大小写、空格、全半角括号、连接符都会归一化）。
认不出来的列名不会被静默丢弃，会进解析报告的「未识别列」。

| 规范字段 | 中文列名 | 必填 | 类型 | 院内可用别名（表头写成任一别名都能认） | 填什么 |
|----------|----------|------|------|--------------------------------------|--------|
| `item_code` | 项目码 | **是** | 文本 | 项目码、项目编码、项目代码、检验项目代码、检验代码、项目编号、itemcode、itemcode | 检验项目码，**与 LIS 上报的 OBX-3 一致**；这是阈值表主键 |
| `item_name` | 项目名 | 否 | 文本 | 项目名、项目名称、检验项目名称、项目中文名、名称、itemname | 项目中文名，用于展示与关键词扩展 |
| `unit` | 单位 | 否 | 文本 | 单位、计量单位、结果单位、unit | 阈值所用单位；与 LIS 上报单位不一致时按换算表换算 |
| `low_critical` | 低危急值 | 否 | 数值 | 低危急值、低危急值下限、低危值、低危急界限、低值危急界限、lowcritical、lowercritical | 低于该值判危急；**留空 = 该项目没有低危急方向** |
| `high_critical` | 高危急值 | 否 | 数值 | 高危急值、高危急值上限、高危值、高危急界限、高值危急界限、highcritical、uppercritical | 高于该值判危急；**留空 = 该项目没有高危急方向** |
| `reference_range` | 参考区间 | 否 | 文本 | 参考区间、参考范围、参考值、正常范围、referencerange、refrange | 参考区间文本，可分性别 / 年龄段；**只作分档与展示，不作判定权威** |
| `effective_from` | 生效日期 | 否 | 日期 | 生效日期、生效时间、生效期、启用日期、effectivefrom、effectivedate | 该版本生效日期；用于按观察时刻选生效版本 |
| `version` | 版本号 | 否 | 文本 | 版本号、版本、版本标识、文件版本、version、ver | 阈值表版本号；**处置卡上必须显示** |
| `effective_to` | 失效日期 | 否 | 日期 | 失效日期、失效期、有效期至、停用日期、effective_to、effectiveto | 该版本失效日期；观察时刻落在生效期与失效日期之间即**版本空档，转人工** |
| `applies_sex` | 适用性别 | 否 | 文本 | 适用性别、性别、性别限定、适用人群性别、sex、gender | 适用人群（男 / 女 / 通用）；留空 = 不按性别分档 |
| `applies_age` | 适用年龄段 | 否 | 文本 | 适用年龄段、年龄段、适用年龄、年龄范围、年龄、age、agerange | 适用年龄段（如 `18-60` / `≥65` / `儿童` / `成人`）；留空 = 不按年龄分档 |

**只认 `item_code` 是必填**：其余列留空不报错，但留空意味着**这一路判定没有依据**，
结果会按「缺阈值 → 不判定 → 转人工」处理，不会被当成不危急。

### 1.3 阈值数值怎么写

| 写法 | 含义 | 例 |
|------|------|-----|
| 裸数字 `30` | **严格不等**：等于 30 **不算**危急 | 钾 6.5 |
| `<30` / `＞30` | 严格不等 | 血红蛋白 `<60` |
| `<=30` / `≤30` | **含等号**：等于 30 **算**危急 | 血小板 `<=30` |
| `>=200` / `≥200` | 含等号 | 肌酐 `>=200` |

**含义差别很大**：院内表里写 `30` 和写 `<=30` 判出来的结果不一样。
拿不准时按院内制度文件的字面意思写，并让检验科组长确认一次。

数值里带单位（`30 g/L`）也能读，但**建议单位单独写在「单位」列**——
带单位的数值会取其中的数字部分，容易和换算表打架。

### 1.4 生效期与多版本

| 场景 | 表里怎么写 | 结果 |
|------|-----------|------|
| 只有一版 | 填 `生效日期` + `版本号`，`失效日期` 留空 | 该日期之后一直生效 |
| 新旧共存 | 旧版填 `失效日期`（= 新版生效日），新版填 `生效日期` | 按观察时刻选版本 |
| **版本空档** | 旧版失效日 < 新版生效日 | 中间时段无生效版本 → **该条转人工**，不猜 |
| 改版不写日期 | 两版都只有版本号 | 按观察时刻选不出版本 → 转人工 |

**版本号要写进表里**（不写在文件名里）：处置卡上要显示「按阈值表 v2.1 判的」，
出处要能被复核。

### 1.5 性别 / 年龄段分档

| 列 | 可用写法 | 读不懂时 |
|----|---------|---------|
| `applies_sex` | `男` / `女` / `男性` / `女性` / `M` / `F` / `通用` / `不限` / 留空 | 该行**不进判定集**，转人工（不猜） |
| `applies_age` | `18-60`、`18-`、`-60`、`≥65`、`<18`、`新生儿`、`小儿`、`儿童`、`成人`、`老年` | 同上 |

区间语义：**下限含、上限不含**（`18-60` = 18 ≤ 年龄 < 60），与参考区间分档口径一致。
写成 `60-18`（反了）会被判成「看不懂」，不会擅自调换 —— 调换等于换语义。

### 1.6 交材料前自检

```bash
# ① 解析一遍，看认出来几行、哪几行没认出来
python3 -m critval.cli ingest --threshold <本院阈值表路径>

# ② 看解析报告（认不出的行逐行列出来）
python3 -m critval.cli kb-watch --dir data/materials      # 不加 --apply 只看事件

# ③ 规则集摘要：缺口条数应为 0
python3 -m critval.cli rules-summary --threshold <本院阈值表路径>
```

| 自检项 | 合格标准 |
|--------|---------|
| 识别行数 | 等于表格里的有效行数（少的就是没认出来的） |
| 未识别列 | 里面没有你指望的字段（认不出的列会被忽略） |
| 缺口条数 | `rules-summary` 显示 0 |
| 未识别行 | 全部在解析报告里逐行可查（**不静默跳过**） |

**未识别行怎么处理**：进人工确认队列，回填后重解析 —— 回填值会真的写回单元格生效，
不是只在队列里记一笔。

```bash
python3 -m critval.cli parse-queue list                       # 看待确认条目
python3 -m critval.cli parse-queue confirm --id <条目ID> --value "<回填值>" --handler "检验科组长"
python3 -m critval.cli parse-queue ignore  --id <条目ID> --handler "检验科组长" --note "理由"
```

## 2. 院内危急值报告制度（docx / pdf）

### 2.1 文件结构

| 项 | 要求 |
|----|------|
| 格式 | `.docx` 或 `.pdf` |
| 结构 | 按「章标题 → 节标题 → 正文段」组织；系统按段落 / 行切开 |
| 条款编号 | `第X条` / `（一）` / `1、` / `1.` 都认；编号用于改版 diff 的配对键 |
| 版本与生效期 | 写在**任何一段**里都行（模板常把版本写在落款处，系统会先扫全文再定版本） |

### 2.2 版本与生效期的写法

系统从全文里扫这三样，**写法固定**：

| 要写的东西 | 写法 | 例 |
|-----------|------|-----|
| 版本号 | `版本：<版本号>` | `版本：v2.1` |
| 生效日期 | `生效日期：<日期>` | `生效日期：2026-01-01`（也认 `2026/01/01`、`2026年1月1日`） |
| 失效日期 | `失效日期：<日期>` | `失效日期：2026-12-31` |

版本号后面跟 `；`、`，`、「生效日期」「编制部门」「说明」「发布日期」或行尾即止。

### 2.3 三项事实字段（处置卡四要素里的三项来自制度）

处置卡要写「通知谁、多久内上报、记录交回哪」，这三样从**条款正文**里认。
正文里出现下面任一说法即视为该条款带了这项事实：

| 规范字段 | 事实标签 | 正文里可用的写法 |
|----------|----------|------------------|
| `notify_target` | 通知对象 | 通知对象、报告对象、接收对象、告知对象 |
| `deadline` | 上报时限 | 上报时限、报告时限、响应时限、时限 |
| `record_destination` | 记录去向 | 记录去向、登记去向、记录位置、记录去处 |

**写法建议**：每条条款里把三样都写全，句子要能被机器认出来：

> 第 5 条　钾结果达到危急值时，**通知对象**为检验科值班技师与临床科室值班护士长，
> **上报时限**为 10 分钟内，**记录去向**为《危急值报告登记本》及护理执行平台。

写不成这样的句子（比如「按规定通知相关科室并及时记录」）系统认不出来 → 该条款缺事实字段，
处置卡会标出「依据缺失」，由人补齐。**系统不会自己编一个通知对象上去。**

### 2.4 制度里点名项目码

条款正文里写检验项目码（如 `718-7`、`63026-5`），该条款就会**只**关联这些项目，
召回时按项目码精确命中；没写项目码的条款走全文检索。

### 2.5 交材料前自检

```bash
# ① 解析制度，看条款数与版本生效期
python3 -m critval.cli policy-summary --policy <本院制度路径>

# ② 试检索：看能不能召回条款、出处带不带文件名与行号
python3 -m critval.cli probe --item <项目码> --value <观察值> --query "危急值上报时限"

# ③ 与旧版比对（改版后跑，看哪些条款变了）
python3 -m critval.cli policy-diff --old <旧版制度> --new <新版制度>
```

| 自检项 | 合格标准 |
|--------|---------|
| 条款数 | 与制度实际条款数差不多（少很多说明段落没被认出来） |
| 版本 / 生效期 | 显示出版本号与生效日期 |
| 试检索 | 能召回条款，出处带**文件名 + 行号 / 条款号 + 版本** |
| 事实字段 | 处置卡四要素齐（阈值行、通知对象、上报时限、记录去向） |

## 3. 材料怎么送进来

### 3.1 放进材料投递目录

```bash
cp 本院危急值阈值表.xlsx data/materials/
cp 本院危急值报告制度.docx data/materials/
```

守护进程按**文件指纹**（sha256）看变化：指纹变了就重装规则集并切快照；
指纹没变就不动（避免每次重启都重装）。

### 3.2 也可以直接配路径

```bash
# .env
CRITVAL_THRESHOLD_PATH=/院内共享目录/本院危急值阈值表.xlsx
CRITVAL_POLICY_PATH=/院内共享目录/本院危急值报告制度.docx
```

### 3.3 送进来的三件事要确认

| 确认 | 命令 | 标准 |
|------|------|------|
| 事件已处理 | `python3 -m critval.cli kb-watch --dir data/materials` | 报出新增 / 变更 / 删除，确认后才 `--apply` |
| 规则集已切换 | `python3 -m critval.cli rules-summary --threshold <表>` | 规则快照 ID 变了、缺口 0 条 |
| 旧事件不受影响 | `python3 -m critval.cli impact-check --old <旧表> --new <新表>` | 换版不改写历史判定，只出影响面清单 |

**历史判定不会被改写**：换版只影响之后的观察时刻。已判过的危急值仍然是当时那版阈值判的，
要复盘用 `impact-check` 与 `judge-replay`。

## 4. 常见退材料原因

| 现象 | 原因 | 怎么改 |
|------|------|-------|
| 一行都没认出来 | 表头不在前 5 行 / 表头列名全是自造词 | 表头提到顶部；列名按 1.2 改 |
| 某几行没认出来 | 缺 `项目码` 或阈值不是数值 | 补项目码；阈值写成纯数字或带比较符 |
| 阈值列认出来但判不了 | 单位与 LIS 上报单位不一致，且换算表里没有 | 在单位换算表里补这一组，或把阈值表单位改成 LIS 上报单位 |
| 规则集有缺口 | 项目码没绑版本 | `bind --item <项目码> --threshold-version <版本> --policy-version <版本>` 建绑定；或确认这个项目本院不报危急值 |
| 生效版本选不出 | 生效期写成自由文本 | 按 1.4 填 `生效日期` / `失效日期` |
| 制度事实字段认不出 | 条款写法太自由 | 按 2.3 把三样事实写成固定说法 |
| 制度条款数明显偏少 | 大量内容放在表格里（docx 表格不抽） | 制度改成段落叙述，或另出一份条款清单 docx |

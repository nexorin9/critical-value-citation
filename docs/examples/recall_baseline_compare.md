# 召回基线对比：纯 BM25 单路 vs 融合引擎

同一份材料、同一份评测集、同一把尺子（`critval.evaluate.evaluate`），只差召回做法：**基线**不做结构化精确匹配、不做规则重排、不做综合分硬闸门；**融合**是产品主路径的混合召回引擎。

## 对比表（三项指标）

| 参赛者 | 命中项数 | Top-5 命中率 | 出处覆盖率 |
|------|----------|--------------|------------|
| 基线（纯 BM25 单路） | 107 / 127（84.3%） | 84.3% | 100.0% |
| 融合引擎（结构化 + 词法 + 重排） | 119 / 127（93.7%） | 93.7% | 100.0% |

## 怎么读这张表

* **出处覆盖率两侧都是 100%** —— 因为出处是在**材料解析时**就挂到每条依据上的（阈值行 / 制度条款），两侧读的是同一份索引。出处覆盖不区分召回做法，它区分的是「这条依据能不能被定位到行」。
* **差值集中在 `threshold_lookup` 一族** —— 那一族问的是「这个检验项目的危急阈值是多少」。单路 BM25 要在几千条近似条款里把阈值依据行排到前面，靠的是词面碰运气；融合引擎有结构化精确路（按项目码查表命中即满分），这类查询是**查表**不是**猜词**。
* **出处覆盖率不是区分点，排序才是** —— 这正是「依据可核对」与「依据排得对不对」两件事：出处保证值班人能翻回原文，排序保证值班人先看到该看的那一条。

## 复算

```bash
python3 scripts/compare_baseline.py
```

同一命令跑两次得到逐字节相同的 `docs/examples/recall_baseline_compare.md` 与 `reports/recall_baseline_compare.csv`（两个产物都不写时间戳）。

口径说明：命中率按**条目数**汇总（逐查询命中数 ÷ 期望条目数，负例不进分母）；Top-N 命中率只数落在前 5 名的期望条目；出处覆盖率只对**带出处引用**的结果计分，出处字段齐备与否按材料类型判定。

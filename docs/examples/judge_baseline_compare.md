## 怎么读这张表

* **误报那几行是告警疲劳的来源** —— LIS 说「异常」，是因为偏离了参考区间；危急阈值比参考区间宽得多。按异常标志推进值班群，真要命的那一条会被淹掉。
* **漏报那几行是「标志不可信」的证据** —— 有些危急值 LIS 自己没标异常（标志字段没填、厂商方言丢了）。只看标志就漏。
* **引擎的「不判定」不是漏报** —— 单位查不到换算关系时，引擎拒绝猜，转人工；基线照样敢下结论。**敢猜**不等于**判得对**。
* **依据可追溯那一列是产品底线** —— 引擎每条危急结论都带「阈值表文件 + 行号 + 版本」，值班人能翻回原文复核；基线给不出依据。

## 复算

```bash
python3 scripts/compare_judge_baseline.py
```

同一命令跑两次得到逐字节相同的 `docs/examples/judge_baseline_compare.md` 与 `reports/judge_baseline_compare.csv`（两个产物都不写时间戳）。

口径说明：样例集由阈值表**确定性生成**（不掺随机数）；真值是样例生成时按**场景意图**标注的，不是拿引擎自己的结论倒推的 —— 所以引擎判错会被这张尺子量出来。误报 = 判危急但真值不危急；漏报 = 判不危急但真值为危急；「该判未判」= 真值明确却转人工。

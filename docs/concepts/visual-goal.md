# 视觉目标卡 · 危急值处置依据检索系统

> 本文件是**结构化视觉目标卡**，不是截图。
> 本运行环境不具备图像生成能力，因此**不产出任何概念图片**，也不放置任何占位图。
> 真实运行截图由任务「采集真实运行截图」采集到 `docs/screenshots/`，不得用本文件的内容冒充实测证据。

**画面类型**：浏览器界面（值班台，同进程内置 HTTP 服务渲染的服务端模板）。
**技术可达性约束**：服务端模板 + 原生 CSS + 原生 SVG 图标；**无前端构建链、无 WebGL、无图表库**。
凡本文件描述的元素，都必须能用 `http.server` + 模板 + CSS 变量真实渲染出来。

## 一、三个状态

### 状态 1 · 起始态（值班台首屏，刚启动未收到事件）

画面上有什么：深灰蓝页头，左侧窄导航栏（事件台账 / 待确认 / 死信 / 材料 / 审计），主内容区顶部一行标题「事件台账」加一句灰字说明，下方是一块**空态**占位区——居中一个线性 SVG 图标（列表轮廓，非 emoji）、主文案「当前没有待处置的危急值事件」、副文案「等待 LIS 推送或 MLLP 监听收单」，下方一枚次级按钮「查看材料绑定状态」。页脚一行等宽小字显示当前规则快照 ID 与配置版本号。

信息层级：页头（一级）→ 区块标题（二级）→ 空态文案（三级）→ 页脚辅助文字（四级）。

### 状态 2 · 首个可用瞬间（处置卡确认页，值班人刚点开推送链接）

画面类型：**两栏**。页头是标题「确认处置 · 事件号」加一句说明，右上角一枚状态徽标「已推送」。

**左栏（主栏 · 依据）**自上而下四块卡片：

1. **处置依据（四要素）**——四个**要素分区**纵向排列，每区左侧一条 3px 语义色竖条（依据齐备走绿 / 降级依据走琥珀 / 依据缺失走红），右上角一枚带文字的徽标写明依据状态，分区下方是值与一行**可展开的出处**（文件名 · 第 N 行 · 版本；展开后是行号、版本、材料指纹前 8 位、章节路径、定位串）。阈值依据行显示项目码与比较式；通知对象显示科室与当班人；上报时限显示粗体分钟数；记录去向显示机构 / 系统名。
2. **口径冲突 · 待人工裁决**——有分歧时逐条摆出两路召回各自的取值、出处与版本，**系统不替人选一个**；无分歧时给一句「两路说法一致」。
3. **版本与生效期**——处置卡快照 ID、阈值表版本、制度版本、配置版本、规则集快照、快照落盘时刻。
4. **处置卡原文（落库快照）**——当时推送出去的那一份，等宽字体、深底色块。

**右栏（副栏 · 动作）**四块卡片：**事件事实**（检验项目 / 观察值 / 科室 / 消息控制号 / 观察时刻 / 当前状态）、**回执状态**（确认人 / 确认时刻 / 回写状态 / 当前状态）、**确认处置**（确认人输入框 + 处置说明输入框 + 一枚实心主按钮「确认处置并回写登记系统」）、**转人工**（默认折叠，展开后是必填原因文本域 + 交接人 + 一枚描边危险色按钮「转人工处理」）。

关键差异：**依据始终在动作左边**——先看依据再点确认的顺序不能反；窄屏（≤1280）收成单栏、依据在前、动作在后。确认页读的是**事件快照**而非现场重新渲染，保证复核时看到的与当时推送的逐字一致。

### 状态 3 · 成形态（事件台账列表 + 概览条 + 筛选）

画面上有什么，自上而下三块：

1. **概览条**——一条细统计条，五个待办桶并排：**待确认 / 已超期 / 待回写 / 失败待处理 / 转人工**，每格是「标签 + 等宽数字」，数字带语义色（待确认与已超期走红、待回写与转人工走琥珀、失败待处理走深灰）。**每一格可点**——点进去钻取到该档的台账视图，且当前筛的科室 / 项目照旧带着走。
2. **筛选表单**——科室 / 检验项目码 / 状态 / 是否超期 / 是否已回写五个原生 select，8px 栅格，右端一枚实心「筛选」与一枚幽灵「重置」。表单走 GET：筛选结果就是这一屏的网址。
3. **明细表**——八列固定：**事件号 / 检验项目 / 结果 / 科室 / 观察时刻 / 上报时限 / 回写 / 状态**。表头吸顶、行 hover 有浅底色、数字列（结果）右对齐并使用等宽数字。上报时限列在超期时追加一枚「已超期」红徽标；回写列给「已回写 / 未回写」徽标 + 回写时刻。

状态列用**带文字的徽标**而非纯色点：危急红「已推送」、琥珀「已确认」、绿「已回写」、深灰「处理失败」。事件号是链接，可点进详情页（事实 / 依据出处 / 推送记录 / 审计流水）。表格下方是分页条：总条数 + 页码 + 上 / 下一页。

## 三、必须可达的约束

1. **不用 emoji 当图标**——所有图标为内联 SVG（线性描边，`stroke-width: 1.5`，`currentColor`）。
2. **不用浏览器默认样式裸奔**——按钮、输入框、表格、select 全部重置；禁用原生 `alert/confirm`，改用站内 toast 容器与模态确认。
3. **徽标不只靠颜色区分**——每个状态徽标必须带中文文字标签，满足夜班与色觉差异场景可读。
4. **数字等宽右对齐**——观察值、上报时限、耗时统一 `font-variant-numeric: tabular-nums` + `text-align: right`。
5. **三态齐备**——加载态用骨架屏（灰底占位条，非转圈动画库）、空态用图标 + 说明 + 行动入口、错误态用错误码 + 可执行建议 + 重试按钮。
6. **响应式两档**——1280px 完整表格 + 展开侧栏；768px 改卡片式列表 + 折叠导航，确认按钮仍可达。
7. **不做的事**——不做 WebGL 3D、不做自定义图表库绘制曲线（数值一律用文本 + 等宽数字）、不做前端构建链打包、不引入 emoji。

## 四、与实测的差距（诚实标注）

本卡描述的是**目标**画面。真实实现由任务「值班台设计 token 与基础组件」（id 48）
「值班台核心界面搭建」（id 49）「值班台 UI 状态与打磨」（id 50）逐条落地。

**已落地（id 48 / id 49）**：token 与基础组件、侧边导航 + 页头 + 内容区的
信息架构、台账页概览条与五桶钻取、五维筛选与分页、八列明细表、确认页两栏
（左依据 / 右动作）、四要素分区与出处展开、口径冲突显式呈现、转人工折叠区。

**已落地（id 50）**：加载骨架屏（首屏 `?bootstrap=1`）、空态（说明 + 下一步
三问）、错误态（错误码 + 可执行建议 + 重试）、站内 toast 反馈（转人工的
琥珀提示）、破坏性操作的站内二次确认模态（不是浏览器原生 confirm）、
768px 窄屏的折叠导航与卡片式列表。

**仍未与本卡逐像素一致的地方**：概览条各格间距、确认页右栏宽度、折叠区
展开后的表单高度、徽标尺寸微调、骨架屏块高、骨架行的列数 —— 本卡是意图，
实测是实物，两者必然有差。

**本卡没写到、但实测里有的**：本卡写「首屏是空态」，而真实运行的台账首屏
是**有数据**的（跑一次就有 4 条事件）—— 空态另有专门一张截图；本卡也没写
「一条标本出两个危急项目合成一张卡」的合并呈现，那是实现里加的。

真实运行截图见 `docs/screenshots/`，由「采集真实运行截图」任务采集，**不得**
用本卡内容或任何设计稿冒充实测证据。采集脚本：`scripts/capture_screenshots.py`。

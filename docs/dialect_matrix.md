# HL7 厂商方言兼容矩阵

国内各 LIS 厂商的 `ORU^R01` 写法差得很多。同一段「危急值结果」报文，换一家
厂商可能落在不同字段：项目码在 `OBX-3` 还是在厂商私有 `Z` 段？标本号在
`OBR-3` 还是在标本段 `SPM-2`？日期写 `20260102083000` 还是 `2026/01/02 08:30`？

本产品把**「字段取哪里」这件事从代码里搬进配置**：一份方言 JSON 描述字段映射、
段差异、日期格式与空值语义，院内换厂商改配置即可，不改代码。

- 方言实现：`critval/hl7/dialects.py`（字段映射的唯一入口）
- 方言配置样例：`samples/dialects/*.json`（8 套，随仓库提交）
- 兼容矩阵对拍：`scripts/parse_matrix.py` → `reports/dialect_diff.csv`
- 协议对拍基线：`samples/dialects/expected.json`（每条帧的参照方言 + 期望字段值）

## 怎么用

```bash
# 1) 跑一遍对拍：每条帧用 8 套方言各解析一遍，逐字段比对
python3 scripts/parse_matrix.py

# 2) 看差异表：哪条帧、哪个方言、哪个字段不同
column -s, -t reports/dialect_diff.csv | head -20

# 3) 院内接入自己的报文：把厂商那份映射写成 JSON 放进 samples/dialects/
#    然后 python3 scripts/parse_matrix.py --dialects 你的目录
```

## 八条已知差异点

| # | 差异点 | 典型表现 | 方言配置项 | 本产品的处理方式 | 验收用例 |
|---|--------|----------|-----------|----------------|----------|
| 1 | 厂商私有 `Z` 段承载项目码 | 项目码不在 `OBX-3`，而在 `ZLR\|1\|718-7\|血红蛋白` 这样的私有段里 | `z_item_code`（段名 / SET-ID 字段 / 项目码字段 / 项目名字段） | 按 SET-ID 与 `OBX-1` 配对取码，标 `medium` 置信度；项目名也从 Z 段取 | `tests/test_dialects.py::test_厂商私有Z段承载项目码` |
| 2 | `OBX-3` 只给中文项目名 | `OBX-3` 写成「白细胞计数」，没有编码 | `item_code` / `item_code_fallback`（兜底链）+ `item_code_pattern`（形态正则） | 中文名不当码用（当项目名），改走 `OBR-4` 通用检验标识兜底，标 `low` 置信度并留痕 | `::test_项目码缺失时走OBR4兜底并标低置信` |
| 3 | 标本号在标本段 | `OBR-3` 留空，标本号写在 `SPM-2` | `specimen_no` / `specimen_no_fallback` | 主链取 `SPM-2.1`，`OBR-3.1` 作为低置信兜底 | `::test_标本号在标本段时按SPM2取值` |
| 4 | 厂商自有日期格式 | `OBX-14` 写 `2026/02/01 10:25` | `date_formats`（`strptime` 格式串集合） | 先按标准 HL7 TS 解析，再按配置集合逐个试；都不中就**不猜**，回落消息时间并留痕 | `::test_厂商日期格式按配置集合解析` |
| 5 | 复合字段用别的分隔符 | `OBX-3` 写成 `718-7:血红蛋白`（冒号而非 `^`） | `extra_component_separators` | 默认只认 `^`；配置里加 `:` 后按冒号拆。默认方言下这串**不当码用**（含中文与冒号），宁可落缺项也不匹配错行 | `::test_冒号分隔的复合字段按方言分隔符拆分` |
| 6 | 空 `OBX` 分组 | 报文尾部混着 `OBX\|2\|\|\|\|\|\|\|`，什么都没有 | `empty_obx_policy`（`skip` / `keep`） | `skip` 跳过但**在消息 notes 里留痕**；`keep` 保留，随后落 `unparsed` 记录 —— 两条路都不静默丢弃 | `::test_空OBX分组按默认策略跳过并留痕` |
| 7 | `OBX-8` 用法不统一 | 异常标志写 `HH`/`LL`，或写 `A^Abnormal^HL70078`，甚至塞了非检验内容 | `obx8` / `obx8_mode`（`advisory` / `ignore`）/ `obx8_vocabulary`（词表） | 只取第 1 个组件；`ignore` 模式整段丢弃；词表把 `HH` 归一成 `H`。**`OBX-8` 永不作判定权威**（判定权威是院内阈值表） | `::test_异常标志按词表归一`、`::test_异常标志整体忽略时字段为空` |
| 8 | 同名段多实例 | 一条消息带两个 `OBR`：前一个是空壳（`OBR\|1\|\|\|\|\|\|`），标本号在第二个里 | 无需配置（默认行为） | 取值时逐个同名段找**第一个非空值**，空壳不再遮蔽后面的数据段 | `::test_空OBR段不遮蔽后续带数据的OBR` |

## 三条通用规则

| 规则 | 为什么 | 落点 |
|------|--------|------|
| **兜底必须标低置信** | `OBR-4` 兜底出来的项目码、`SPM-2` 兜底出来的标本号，都是「猜」的 | 事件行落 `item_code_source` / `item_code_confidence` / `specimen_no_source` / `specimen_no_confidence`；处置卡上标「项目码来自 OBR-4.1 兜底匹配（低置信，需人工核对）」 |
| **不认识就不猜** | 日期不在格式集合里、字段号越界、值落在空值字面量集合里 —— 一律当缺 | 落 `unparsed` 记录 + 写审计，值班台能看到「今天有几条报文没读懂、缺了什么」 |
| **`OBX-8` 不参与判定** | 异常标志口径各厂商不一，且阈值表才是判定权威 | 判定引擎只读阈值表；`OBX-8` 仅供交叉校验与筛选（任务 id 9 做口径分歧检出） |

## 兜底链的适用范围（`item_code_fallback_scope`）

`OBR-4` 是**订单级**的通用检验标识，一条消息里有多个结果时，它归属不到具体
某一条。官方样例报文正是这种情况：`OBR-4` 是过敏原组合标识，同一条消息里还
跟着心率、血氧等生命体征结果 —— 硬兜底会把组合标识安到不相干的结果上。

因此默认只在「一条消息一条结果」时兜底（`single_obx`）；院内确认本院报文形态
后可在配置里改成 `all`。默认口径下，多结果报文里缺项目码的那几条会落
`unparsed` 转人工，而不是被安上别人的项目码。

## 时刻口径

一条报文里 `OBX-14`（无时区偏移）与 `MSH-7`（带 `+0100` 偏移）会同时出现。
本产品把两者统一归到**发送方本地墙钟时间**（去掉偏移、保留读数）：一部分带
时区、一部分不带，判定规则按生效期比较时会抛 `TypeError`（naive 与 aware
不能比）。

## 对拍怎么读

`scripts/parse_matrix.py` 产出两条线：

| 比对口径 | 参照值 | 含义 | 要求 |
|----------|--------|------|------|
| **期望基线** | `samples/dialects/expected.json` 里每条帧的字段值 | 参照方言的解析结果与期望**逐字段一致** | 差异必须为 0（退出码 0） |
| **方言互拍** | 同帧参照方言的解析结果 | 换方言后哪些字段变了 | 全部落 `reports/dialect_diff.csv`，供院内选方言、改配置 |

参照方言按帧指定：官方样例报文用 `default`，其余帧指向它要考的那套厂商方言。
所以「默认方言差异数为 0」这条验收，在官方样例报文上由 `default` 直接承担。

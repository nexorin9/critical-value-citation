# 命令与接口参考（CLI 子命令 · 接口端点 · 错误与降级）

> 本文件是 `README.md` 的技术附录：README 里只留速查表与常用入口，完整参数、
> 接口契约与失败语义在这里。退出码约定：`0` 成功 / `1` 业务异常（事情本身没办成 —— 凭据缺失、待回执没清、断链、没召回到依据）/ `2` 参数错（命令或参数写错）。带 `--json` 时 stdout 上**只有一个** JSON 文档，顶层固定带 `command` / `ok` / `exit_code` 三个保留键 —— 脚本可以只看 `exit_code` 就判成败，不必解析业务文案。

## CLI 子命令与接口端点

### CLI 子命令与接口端点

| 命令或路径 | 用途 | 关键参数 |
|------------|------|----------|
| `python -m critval.daemon` | **常驻守护进程（运行主路径）**：MLLP 监听 + 目录投递 + 定时器三路事件源汇入**有界队列**，并发处理（判定 → 出卡 → 推送），周期心跳；同进程挂值班台（台账页 / 详情页 / 确认页）与入站推送端点；停机时处理完在途事件再退，重启后**按台账状态续跑**不重复推送 | `--db`、`--threshold`、`--policy`、`--frame-dir`、`--material-dir`、`--snapshot-dir`、`--mllp-bind`、`--console-host`、`--console-port`、`--workers`、`--queue-size`、`--heartbeat-seconds`、`--timer-interval-seconds`、`--no-console`、`--run-seconds`、`--log-file`、`--log-dir`、`--log-max-bytes`、`--log-backup-count`、`--heartbeat-path`、`--lock-path`、`--no-lock`、`--shutdown-grace-seconds` |
| `critval ingest` | **材料与报文入库**：`--threshold` 解析阈值表 → 解析报告（识别行数 / 未识别列 / **未识别行逐行列出**）；`--policy` 解析院内制度 → 条款清单与未识别段落；`--frames` 把目录里的 ER7 帧批量灌进台账（与守护进程同一条入站路径，幂等键挡重复）；**`--dir <目录>` 是批处理模式** —— 默认启用断点续跑游标（`data/ingest_cursor.json`），批量回灌中途被打断后重跑同一条命令即从断点继续，不重复灌已处理过的帧 | `--threshold`、`--policy`、`--frames`、`--dir`（批处理目录，默认启用续跑游标）、`--db`、`--cursor`（断点续跑游标路径）、`--rate-limit`（帧/秒）、`--json` |
| `critval kb-watch` | **投递目录扫描（当前可用）**：按文件 sha256 比对得出新增 / 变更 / 删除事件；不加 `--apply` 只报事件不动任何东西，加了才重建（重解析 → 落解析报告 → 疑点入队 → 规则集重编译并原子切换） | `--dir`、`--apply`、`--queue`、`--catalog`、`--report-dir`、`--json` |
| `critval parse-queue` | **材料解析人工确认队列（当前可用）**：`list` 列出疑点（未识别行 / 字段缺失行 / 没认出的列 / 疑似合并单元格 / 疑似多版本）；`confirm` 回填并**触发重解析**（回填生效与否照实报）；`ignore` 忽略（必须写处理人） | `list --status --source`、`confirm --id --value --handler --note`、`ignore --id --handler --note`、`--queue`、`--report-dir`、`--json` |
| `critval bind` | **版本绑定表（当前可用）**：绑定检验项目码 → 阈值表版本 + 制度版本；绑定后未绑版本不参与召回。`--list` 只看绑定表；`--item/--threshold-version/--policy-version` 手工绑定一条；`--derive --threshold --policy --at` 按观察时刻从材料推导一份 | `--bindings`、`--item`、`--threshold-version`、`--policy-version`、`--derive`、`--threshold`、`--policy`、`--at`、`--list`、`--json` |
| `critval policy-summary` | **制度解析摘要（当前可用）**：把院内危急值报告制度（docx / pdf）解析成条款级条目，输出识别条款数、未识别行清单、字段缺失清单与版本生效期 | `--policy`、`--json` |
| `critval policy-diff` | **制度改版影响面（当前可用）**：两版制度按稳定标识逐条对齐，列出新增 / 删除 / 事实要素变化 / 正文修订，可落 CSV | `--old`、`--new`、`--csv`、`--json` |
| `critval probe` | **试检索回放（不落库、不改状态）**：先摆出**参与召回的材料版本**（文件名 + 指纹 + 条目数），再给按项目码的候选、得分、命中路与出处定位；召回不到依据时明说「未召回到依据」，一条依据都不编。**`--item <项目码>` + `--value <观察值>`（可写成 `25 g/dL`）额外按同一份阈值表试判这条结果** —— 给出结论（危急 / 不危急 / 不判定转人工）与命中的阈值行出处（文件名 + 行号 + 版本）；单位换不了、阈值表没收录、项目码写错一律**不判定**，不猜一个系数 | `--item`、`--item-code`、`--value`、`--unit`、`--at`（观察时刻，决定按哪一版阈值表试判）、`--query`、`--threshold`、`--policy`、`--top-n`、`--top-k`、`--similarity-threshold`、`--keywords-weight`、`--json` |
| `critval replay` | **批量重放 ER7 帧目录**：读帧 → 规范化 → 判定 → 落台账 → 出卡，走的是与守护进程**同一条**入站路径；输出新增事件 / 幂等跳过 / 未识别 / 失败与吞吐；给 `--cursor` 即断点续跑（文件内容变了游标作废、从头重放） | `--frames`、`--threshold`、`--db`、`--cursor`、`--rate-limit`、`--json` |
| `critval export` | 导出处置卡快照（按事件取回**当时推送的原文**，不重新渲染）：text 纯文本 / markdown 企微原文 / html 值班台片段 | `--event`、`--format`、`--snapshot-dir`、`--verify` |

### 错误与降级

**退出码约定**（所有运维子命令统一）：`0` 成功 / `1` 业务异常（事情本身没办成 —— 凭据缺失、待回执没清、断链、没召回到依据）/ `2` 参数错（命令或参数写错）。带 `--json` 时，stdout 上**只有一个** JSON 文档，顶层固定带 `command` / `ok` / `exit_code` 三个保留键 —— 脚本可以只看 `exit_code` 就判成败，不必解析业务文案。

| 场景 | 表现 | 处理方式 |
|------|------|----------|
| 命令行参数写错（少了必填项 / 拼错子命令） | argparse 直接报用法错误 | 退出码 `2`，错误提示指明缺哪个参数；不会带着半截配置往下跑 |
| 给了 `--json` 但命令中途失败 | stdout 上不是完整 JSON | 失败信息走 stderr，stdout 仍是一个可解析的 JSON 文档（`ok=false`、`exit_code=1`），脚本不会解析崩 |
| 观察值单位查不到换算关系 | 不出判定结论 | 标「单位未知」，事件转「转人工」，不猜系数 |
| LIS 异常标志与院内阈值表口径对不上 | 结论**以阈值表为准**，同时留一条口径分歧记录（说明带命中阈值行的文件与行号） | 判定结论照常出；分歧随判定理由落台账，方向区分「多报」与「漏报」，供值班人复核 |
| 同一标本同一项目同一时刻出现两个互斥结果 | **不自动判定、不出卡** | 结论标「观察值互斥」，事件转「转人工」，写一条互斥审计；两个数值分处危急阈值两侧时标为强冲突 |
| 修正结果（带修正标记的重发结果）到达 | 重新判定并接上取代关系 | 旧事件定格在终态「已被取代」，判定与出处原样保留；旧事件若已被值班人确认过则**不改写**，照常落台账并转人工裁决 |
| 试图把已被取代 / 已归档的事件改回别的状态 | 拒绝迁移（终态不可静默回退） | 抛终态保护错误并说明当前终态；确需迁移必须显式声明 |
| 想跳过中间环节改状态（如没推送就写成已确认） | 拒绝迁移（跳步） | 抛非法跃迁错误并写明起止状态与合法去向；事件状态**原样不动**，不写半截状态 |
| 往审计里写患者姓名 / 身份证 / 住院号 | 患者明细混进留痕 | **拒写**（不是脱敏）：报「审计说明文字出现患者可识别信息」并指出命中的特征；审计表本身由库级触发器锁成只追加 |
| 回放一条**没有节点级轨迹**的事件 | 回放查不到这一步的过程 | 明说「这条事件不是经处置链跑进来的」并以业务失败码退出，**不编**一条假轨迹；台账不存在则按用法错误退出 |
| 多条线程同时收同一帧危急值 | 可能落两条事件、推两张卡 | 幂等键上的 UNIQUE 约束把住：恰好一路插进去，其余按「重复到达」处理（不抛栈、不覆盖既有事实） |
| 同一张卡被推出去后又到期重推 | 「今天推送了多少条」被灌大 | 重推另起一条推送记录，首次推送时刻不被覆盖；统计里**去重事件数**与**真实尝试次数**分开列 |
| 阈值恰等于危急值边界 | 按表内开闭区间语义判（裸数字取严格不等） | 写 `< 30` 时等于 30 **不算**危急；写 `≤ 30` 时等于 30 **算**危急，语义跟着院内阈值表走 |
| 观察值落在阈值表未覆盖的项目 | 出不了阈值依据行 | 卡片该要素标「缺失」，写明未命中阈值表，事件转「转人工」 |
| 制度条款一条都没召回 | 出不了时限与去向 | 不产出任何引用，转「转人工」并留审计，绝不编依据；卡片标注走了第几级降级 |
| 原样查不到制度依据（多半是问法对不上） | 严格闸门下召回为空 | 逐级降级：关键词扩展（院内术语表自动成对）→ 章节级兜底（按项目码定位制度章节）→ 转人工；每条依据带层级，卡片写明第几级找到的 |
| 排班系统不可用 | 取不到当班人 | 降级为带时间戳的缓存，卡片标注「当班名单来源：缓存（时间戳）」并把该要素标为**降级**；缓存过期仍不可用则**转人工**（不拿三小时前的旧名单冒充当前当班人） |
| 排班系统凭据不对（401） | 取不到当班人 | 同样降级到缓存，但错误文案写明 `401` —— 值班人看得出是**该换凭据**还是**对端挂了** |
| 值班人还没确认就想回写登记系统 | 未确认的回执会变成登记系统里的已生效事实 | **一次出站调用都不发**（出站请求数为 0），只回报「当前状态不允许回写」；未确认就是未确认 |
| 值班台台账空着（一条记录都没有） | 分不清是「今天没危急值」还是「链路没通」 | 走**空态**：说清这可能是哪一种空（LIS 推没推 / MLLP 监听在不在跑 / 阈值表版本绑没绑），逐条列出排查项与下一步；**筛完为空**另走表内空态提示放宽筛选 —— 两者不混成一句「暂无数据」 |
| 阈值表路径配了但文件读不到 | 规则集没绑版本，判定会直接转人工、不会产出危急值事件 | 值班台**显式报错**（错误码 `threshold_unbound` + 怎么办 + 重试入口），不让值班人对着空台账以为今天没事 |
| 处置卡快照缺失 / 快照目录没配 | 确认页上没有可复核的依据 | 走**错误态**并分清两种情况（目录没配 → `CRITVAL_SNAPSHOT_DIR`；文件丢了 → 人工核对阈值表与制度）；页面**不重新渲染**一张新的糊弄过去 |
| 值班人点「补写回写」但补写通道没接 | 出站回写发不出去 | 回 `503` + 错误码 `replay_unavailable`，明说凭据位没配；**不假装补上了**，本条留在待写队列里 |
| 补写回写仍然失败 | 回执还是没进登记系统 | 错误码 `replay_failed` + 失败深灰的 toast；**本条不丢弃**（仍是待回写）、状态不被悄悄改掉，原因进审计流水 |
| 转人工 / 补写没填原因 | 交接没有交接的样子，事后答不上「这条为什么停在这儿」 | 服务端 **400 拒收** + 错误码 `reason_required`；**二次确认是站内模态框，不是浏览器原生 confirm** —— 没有 JS 时表单照常提交，服务端照样拒收 |
| 值班台凭据缺失或不匹配 | 页面拿不到台账 | `401` + 提示条说明凭据怎么带（`Authorization: Bearer` 或 `?token=`）；未配 `CONSOLE_TOKEN` 则本机直开 |
| 制度是 pdf 但环境没装 pypdf | 制度条款读不出来 | **显式降级**：报「制度解析降级：…pypdf…」，不静默返回「这份制度里没有条款」；该次引用标为无依据并转人工 |
| 制度条款只写了一半事实（只有时限，没写通知对象与去向） | 处置卡拿不全三要素 | 该条款标「字段缺失」并写明缺哪两项，处置卡对应要素标缺项，**不拿别的条款的取值顶替** |
| 制度版本落在两个版本的生效期空档 | 取不到可用制度版本 | 不取就近版本，转人工并记版本空档 |
| 阈值表版本落在两个版本的生效期空档 | 取不到可用版本 | 不取就近版本，转人工并记版本空档 |
| 同一张处置卡引用了同一类材料的两个版本 | 依据口径自相矛盾（改版前后混用） | **拒绝出卡**，报 `version_mismatch`，不出矛盾的卡 |
| 处置卡引用的版本对不在院内声明的版本绑定内 | 阈值表与制度不是配套的那一版 | **拒绝出卡**，报 `version_mismatch`；阈值表与制度各自独立编号、院内未声明绑定时只标「需人工核对」，不误拦 |
| 引用了未绑版本的条款 / 阈值行 | 依据来自没绑定的版本 | 绑定生效时**只召回被绑版本**，未绑版本不进引用；若已混进卡里 → 版本闸门拒绝出卡 |
| 同一份材料重复投递（内容没变） | 指纹比对判定为「没变」 | 不产生事件、不重复入库、不重复出报告、不重复入队 —— 重复投递不冲淡版本号 |
| 阈值表里同一项目码挂着两个版本号 | 哪一版说了算不确定 | 解析报告标「疑似多版本」，进人工确认队列，**不自动选版本** |
| 阈值表里项目码列做了合并单元格 | 下面几行读不成阈值行 | 解析报告标「疑似合并单元格」（判据读工作簿 `mergeCells` 元数据，不是猜的），进队列等人确认 |
| 人工回填的值表里根本没有那一列 | 回填写不进去 | 重解析报「回填未生效」并写明原因，**不装作成功**；疑点保持待处理 |
| 回放时事件在、判定记录不在 | 多半是判定留痕功能上线前入库的旧事件 | 明确报「该事件没有判定记录」并以失败码退出，**不拿重算结果冒充当时的记录** |
| 对账时登记系统连不上 / 鉴权被拒 | 回执一条都读不到 | **报错退出**，不出一份「本地已确认但远端没有」的假清单 —— 查不到 ≠ 没有，假清单会让人白补写一遍 |
| 对账时个别条目回执查不到 | 那几条的远端状态未知 | 该条**不判差异**（不判成「远端没有」），摘要写明「有 N 条未判定」；其余条目照常比对 |
| 登记系统不支持列全部回执 | 查不出「远端有、本地没有」这一类 | 自动降级为按消息控制号逐条查，并在摘要里写明降级原因与未检出的差异类型 |
| 回放时材料已经换过 | 重算结论与落库记录对不上 | 逐条列出差异字段（结论 / 阈值行 / 材料指纹 …）并非零退出；历史那次的判定记录原样保留，**不自动改写** |
| LIS 异常标志与阈值表判定不一致 | 两边说法不同 | 以阈值表为准，留一条口径分歧记录（异常标志只作筛选与交叉校验） |
| 同一标本同一项目同一时刻出现互斥值 | 结论无法唯一确定 | 标「观察歧义」，不自动判定、不出卡 |
| 结果状态为修正（`C`） | 旧结论已过期 | 重新判定，新事件标记取代关系，旧事件置「已被取代」，终态不静默回退 |
| 企微推送失败 | 值班群收不到 | **限流（45009）与网络抖动按指数退避重试**（默认 3 次，基数 0.5 秒、倍数 2、单次封顶 8 秒）；**凭据错 / webhook 非法不重试**（重试一万次也是一样的错）；仍推不出去则落**本机通知记录**并写明失败原因，事件不丢 |
| 值班群被同一个事件刷屏 | 同一条危急值连着推好几遍 | **重复投递抑制**：抑制键 = 事件 ID + 投递状态 + 尝试轮次；同一轮次只允许推一次，第二次**根本没发出去**（`suppressed`），值班台与台账都看得到 |
| 首次推送成功后，到期复查重推被误判成重复 | 值班人没看见的那条永远躺在台账里 | 抑制键带**投递状态**：首次推送是 `initial:1`、到期重推是 `retry:1` / `retry:2`，**各占一把锁，互不抑制** |
| 重试全部失败（推不出去） | 危急值卡在「没人知道」 | **落死信**（原卡内容 + 最后一次错误 + 尝试次数）+ 事件落「处理失败」等人工处理 + 写告警审计；**事件绝不静默丢弃**（仍在台账里）；处置卡正文同时落**本机通知队列**，值班台可见 |
| 推送进程崩在推送中途 | 这条危急值再也推不出去 | 投递轮次停在「在途」；超过陈旧窗口（默认 300 秒）允许重新抢占 —— 宁可重推一次（抑制键兜底，不刷屏），也不让事件卡死 |
| 已被值班人确认的事件又遇推送失败 | 自动路径会不会把既成事实改回失败态 | **不改**：状态迁移只落合法路径，已确认的事件保持「已确认」原样，死信与告警照留（既成事实不可被自动路径改写） |
| 企微返回 HTTP 200 但 `errcode` 非 0 | 以为推成了，其实没推到 | **按失败处理**（企微用 `errcode` 表达成败，不看 HTTP 状态码）；响应不是合法 JSON 同样判失败 |
| 登记系统回写返回 4xx | 契约不匹配 | 落「回写失败」且**不重试**，提示人工改数据；**已确认回执不丢**（确认人 / 确认时刻 / 通知对象 / 上报时限原样留在台账里），可补写 |
| 登记系统回写失败 | 这条回执没能变成已生效事实 | 台账落「回写失败」并写审计；**幂等键仍是消息控制号**，补写时登记系统按同一个键覆盖，**不会生成第二条** |
| 项目紧急度表某一行的权重不是数值 | 那一项排不进优先级 | **只跳过该行**并留告警（写明第几行没采用），其余行照常采用；整张表都不可用时回退内置示例表并告警 —— 一张坏表不会让排序排不出来 |
| 项目紧急度表文件不存在 | 没有院内紧急度口径 | 用内置示例表（零告警）；院内上线按 `samples/urgency.csv.example` 复制到 `data/urgency.csv` 维护 |
| 合并时间窗配了非法值（非数字 / 负数） | 合并边界算不准 | 回落默认 300 秒，告警写明配了非法值 —— 不用一个猜出来的窗口把不同标本并到一张卡 |
| 合并后某一项的依据取不到 | 卡内这一项没有阈值行 | **该项**标「依据缺失」并写明原因，其余项照常显示（不用占位文案冒充已解决）；缺的是整张卡的共享要素（如没有制度条款）时同样标缺项 |
| 登记系统回写返回 5xx 或超时 | 服务端暂时不可用 | 落「回写失败」并留待补写清单；对端恢复后按同一幂等键补写，状态推进到「已回写」 |
| 回写时同一消息控制号内容与既有记录不一致 | 幂等冲突 | 记冲突并转人工，既有事实不被覆盖、不被改写 |
| 值班人迟迟未确认 | 卡片停在待回执 | 按上报时限到期复查重推；重推不重复计数、不覆盖原推送记录，也不被首推抑制 |
| 值班台未配置访问令牌 | 页面可能被越权访问 | 启动自检列出缺失凭据位，给出可执行补齐提示 |
| 入站推送没带或带错 Bearer 凭据 | LIS 推不进来 | 回 `401` 并写审计（只记来源地址与路径，**不记 token 明文**）；服务端没配 `LIS_CRITICAL_TOKEN` 时一律拒绝，不给默认口令 |
| 入站推送请求体超限 | 一次异常大包打满内存 | 回 `413`，**不把 body 读进内存**并断开连接 |
| 入站推送缺必填字段 | 这条结果读不懂 | 回 `422` 并落 `unparsed` 记录 + 写审计；**一条都不静默丢弃**，值班台能看到今天有几条推送没读懂、缺了什么 |
| 入站推送里带了患者标识字段 | 患者信息混进只传结果的通道 | 当场拒绝（`422`）并说明本通道只传结果字段 |
| 同一事件被 LIS 重复推送 | 值班群刷屏、台账长两条 | 幂等键 `event_id + item_code + raised_at`；重复推送回 `200` 带重复标识，不重复判定、不重复出卡、不重复推送，既有事实不被覆盖 |
| LIS 一次 TCP 读带回好几帧（粘包） | 帧边界错位，报文被拼在一起 | 按结束符逐帧切出，**一帧都不少** |
| 一帧被拆成好几次 TCP 读（拆包） | 读到半条报文就当成完整帧 | 读到结束符之前**不交帧**，留在缓冲区等下一次 |
| 收到空帧或帧前垃圾字节 | 这段字节不含报文 | 跳过但留痕（`empty_frame` / `garbage_prefix`），**不静默丢** |
| 连接断开时缓冲区还剩半个帧 | 半个报文被当成完整帧处理 | 记 `incomplete_frame` 留痕，不当报文处理 |
| 单帧超过上限（默认 1 MiB） | 异常大包打满内存 | 丢弃并留痕（`oversized_frame`），重新对齐后续帧，不吞掉后面的报文 |
| 厂商 `OBX-3` 只给中文项目名 | 拿项目名查阈值表必然查不到 | 按阈值表**项目名**匹配到项目码，标低置信「需人工核对」；匹配不上或命中多条 → 转人工，**不把危急值安到别的项目上** |
| LIS 侧 REST 回调返回 4xx | 契约不匹配 | **不重试**（重试也没用），提示人工改数据 |
| LIS 侧 REST 回调返回 5xx / 不可达 | 对端暂时不可用 | 标记为**可重试**，交给上层退避重试 |
| 处置链某一环拿不到该拿的东西 / 交出来的结果形状不对 | 空值顺着链传下去，最后在不相干的地方炸掉 | **当场停在那一环**：该节点与它后面的节点**一个都不跑**，报错带**节点名与字段名**；事件落「转人工」并写审计 `flow_contract_violation`；审计明细写明这一环**能不能重试**（判定这类纯计算环节重跑还是同一个答案 → 不可重试；推送与回写幂等 → 可重试） |
| 链上写错了必填参数 | 配置错了还硬跑 | 立即抛错停住（不改配置就别继续跑），事件仍落转人工并写审计 `flow_param_invalid` |
| 同一个数据目录起了第二个守护进程 | 两套进程各推各的 → 值班群收到两张一样的卡，值班人不知道该按哪一张 | 第二个实例**明确报错退出**（退出码 3）：报出占着目录的进程号、主机与启动时刻；旧实例停机后锁自动释放，可正常再起 |
| 收到停机信号（SIGTERM）时还有事件在队列里 | 危急值已经在队列里了，丢掉就等于漏处置 | **先拒收新事件**（拒收留痕），再在宽限期内把队列排空；宽限期到了还没处理完的**明确留痕**（`daemon_shutdown_abandoned`），不静默消失、不算处理成功 |
| 值班机磁盘被日志吃满 | 台账写不进去、快照存不下，危急值直接进不来 | 日志**按大小滚动**（`CRITVAL_LOG_MAX_BYTES` / `CRITVAL_LOG_BACKUP_COUNT`），旧日志留档不自动清空 |
| 出站依赖（排班系统 / 登记系统 / 企微）连不上 | 处置卡的「通知对象」或回执推不出去 | 健康检查标 `degraded` 并写清哪个依赖不通（**未配置**不算故障）；推送侧另有本机队列兜底，事件不丢 |

## 错误与降级

### 错误与降级

**退出码约定**（所有运维子命令统一）：`0` 成功 / `1` 业务异常（事情本身没办成 —— 凭据缺失、待回执没清、断链、没召回到依据）/ `2` 参数错（命令或参数写错）。带 `--json` 时，stdout 上**只有一个** JSON 文档，顶层固定带 `command` / `ok` / `exit_code` 三个保留键 —— 脚本可以只看 `exit_code` 就判成败，不必解析业务文案。

| 场景 | 表现 | 处理方式 |
|------|------|----------|
| 命令行参数写错（少了必填项 / 拼错子命令） | argparse 直接报用法错误 | 退出码 `2`，错误提示指明缺哪个参数；不会带着半截配置往下跑 |
| 给了 `--json` 但命令中途失败 | stdout 上不是完整 JSON | 失败信息走 stderr，stdout 仍是一个可解析的 JSON 文档（`ok=false`、`exit_code=1`），脚本不会解析崩 |
| 观察值单位查不到换算关系 | 不出判定结论 | 标「单位未知」，事件转「转人工」，不猜系数 |
| LIS 异常标志与院内阈值表口径对不上 | 结论**以阈值表为准**，同时留一条口径分歧记录（说明带命中阈值行的文件与行号） | 判定结论照常出；分歧随判定理由落台账，方向区分「多报」与「漏报」，供值班人复核 |
| 同一标本同一项目同一时刻出现两个互斥结果 | **不自动判定、不出卡** | 结论标「观察值互斥」，事件转「转人工」，写一条互斥审计；两个数值分处危急阈值两侧时标为强冲突 |
| 修正结果（带修正标记的重发结果）到达 | 重新判定并接上取代关系 | 旧事件定格在终态「已被取代」，判定与出处原样保留；旧事件若已被值班人确认过则**不改写**，照常落台账并转人工裁决 |
| 试图把已被取代 / 已归档的事件改回别的状态 | 拒绝迁移（终态不可静默回退） | 抛终态保护错误并说明当前终态；确需迁移必须显式声明 |
| 想跳过中间环节改状态（如没推送就写成已确认） | 拒绝迁移（跳步） | 抛非法跃迁错误并写明起止状态与合法去向；事件状态**原样不动**，不写半截状态 |
| 往审计里写患者姓名 / 身份证 / 住院号 | 患者明细混进留痕 | **拒写**（不是脱敏）：报「审计说明文字出现患者可识别信息」并指出命中的特征；审计表本身由库级触发器锁成只追加 |
| 回放一条**没有节点级轨迹**的事件 | 回放查不到这一步的过程 | 明说「这条事件不是经处置链跑进来的」并以业务失败码退出，**不编**一条假轨迹；台账不存在则按用法错误退出 |
| 多条线程同时收同一帧危急值 | 可能落两条事件、推两张卡 | 幂等键上的 UNIQUE 约束把住：恰好一路插进去，其余按「重复到达」处理（不抛栈、不覆盖既有事实） |
| 同一张卡被推出去后又到期重推 | 「今天推送了多少条」被灌大 | 重推另起一条推送记录，首次推送时刻不被覆盖；统计里**去重事件数**与**真实尝试次数**分开列 |
| 阈值恰等于危急值边界 | 按表内开闭区间语义判（裸数字取严格不等） | 写 `< 30` 时等于 30 **不算**危急；写 `≤ 30` 时等于 30 **算**危急，语义跟着院内阈值表走 |
| 观察值落在阈值表未覆盖的项目 | 出不了阈值依据行 | 卡片该要素标「缺失」，写明未命中阈值表，事件转「转人工」 |
| 制度条款一条都没召回 | 出不了时限与去向 | 不产出任何引用，转「转人工」并留审计，绝不编依据；卡片标注走了第几级降级 |
| 原样查不到制度依据（多半是问法对不上） | 严格闸门下召回为空 | 逐级降级：关键词扩展（院内术语表自动成对）→ 章节级兜底（按项目码定位制度章节）→ 转人工；每条依据带层级，卡片写明第几级找到的 |
| 排班系统不可用 | 取不到当班人 | 降级为带时间戳的缓存，卡片标注「当班名单来源：缓存（时间戳）」并把该要素标为**降级**；缓存过期仍不可用则**转人工**（不拿三小时前的旧名单冒充当前当班人） |
| 排班系统凭据不对（401） | 取不到当班人 | 同样降级到缓存，但错误文案写明 `401` —— 值班人看得出是**该换凭据**还是**对端挂了** |
| 值班人还没确认就想回写登记系统 | 未确认的回执会变成登记系统里的已生效事实 | **一次出站调用都不发**（出站请求数为 0），只回报「当前状态不允许回写」；未确认就是未确认 |
| 值班台台账空着（一条记录都没有） | 分不清是「今天没危急值」还是「链路没通」 | 走**空态**：说清这可能是哪一种空（LIS 推没推 / MLLP 监听在不在跑 / 阈值表版本绑没绑），逐条列出排查项与下一步；**筛完为空**另走表内空态提示放宽筛选 —— 两者不混成一句「暂无数据」 |
| 阈值表路径配了但文件读不到 | 规则集没绑版本，判定会直接转人工、不会产出危急值事件 | 值班台**显式报错**（错误码 `threshold_unbound` + 怎么办 + 重试入口），不让值班人对着空台账以为今天没事 |
| 处置卡快照缺失 / 快照目录没配 | 确认页上没有可复核的依据 | 走**错误态**并分清两种情况（目录没配 → `CRITVAL_SNAPSHOT_DIR`；文件丢了 → 人工核对阈值表与制度）；页面**不重新渲染**一张新的糊弄过去 |
| 值班人点「补写回写」但补写通道没接 | 出站回写发不出去 | 回 `503` + 错误码 `replay_unavailable`，明说凭据位没配；**不假装补上了**，本条留在待写队列里 |
| 补写回写仍然失败 | 回执还是没进登记系统 | 错误码 `replay_failed` + 失败深灰的 toast；**本条不丢弃**（仍是待回写）、状态不被悄悄改掉，原因进审计流水 |
| 转人工 / 补写没填原因 | 交接没有交接的样子，事后答不上「这条为什么停在这儿」 | 服务端 **400 拒收** + 错误码 `reason_required`；**二次确认是站内模态框，不是浏览器原生 confirm** —— 没有 JS 时表单照常提交，服务端照样拒收 |
| 值班台凭据缺失或不匹配 | 页面拿不到台账 | `401` + 提示条说明凭据怎么带（`Authorization: Bearer` 或 `?token=`）；未配 `CONSOLE_TOKEN` 则本机直开 |
| 制度是 pdf 但环境没装 pypdf | 制度条款读不出来 | **显式降级**：报「制度解析降级：…pypdf…」，不静默返回「这份制度里没有条款」；该次引用标为无依据并转人工 |
| 制度条款只写了一半事实（只有时限，没写通知对象与去向） | 处置卡拿不全三要素 | 该条款标「字段缺失」并写明缺哪两项，处置卡对应要素标缺项，**不拿别的条款的取值顶替** |
| 制度版本落在两个版本的生效期空档 | 取不到可用制度版本 | 不取就近版本，转人工并记版本空档 |
| 阈值表版本落在两个版本的生效期空档 | 取不到可用版本 | 不取就近版本，转人工并记版本空档 |
| 同一张处置卡引用了同一类材料的两个版本 | 依据口径自相矛盾（改版前后混用） | **拒绝出卡**，报 `version_mismatch`，不出矛盾的卡 |
| 处置卡引用的版本对不在院内声明的版本绑定内 | 阈值表与制度不是配套的那一版 | **拒绝出卡**，报 `version_mismatch`；阈值表与制度各自独立编号、院内未声明绑定时只标「需人工核对」，不误拦 |
| 引用了未绑版本的条款 / 阈值行 | 依据来自没绑定的版本 | 绑定生效时**只召回被绑版本**，未绑版本不进引用；若已混进卡里 → 版本闸门拒绝出卡 |
| 同一份材料重复投递（内容没变） | 指纹比对判定为「没变」 | 不产生事件、不重复入库、不重复出报告、不重复入队 —— 重复投递不冲淡版本号 |
| 阈值表里同一项目码挂着两个版本号 | 哪一版说了算不确定 | 解析报告标「疑似多版本」，进人工确认队列，**不自动选版本** |
| 阈值表里项目码列做了合并单元格 | 下面几行读不成阈值行 | 解析报告标「疑似合并单元格」（判据读工作簿 `mergeCells` 元数据，不是猜的），进队列等人确认 |
| 人工回填的值表里根本没有那一列 | 回填写不进去 | 重解析报「回填未生效」并写明原因，**不装作成功**；疑点保持待处理 |
| 回放时事件在、判定记录不在 | 多半是判定留痕功能上线前入库的旧事件 | 明确报「该事件没有判定记录」并以失败码退出，**不拿重算结果冒充当时的记录** |
| 对账时登记系统连不上 / 鉴权被拒 | 回执一条都读不到 | **报错退出**，不出一份「本地已确认但远端没有」的假清单 —— 查不到 ≠ 没有，假清单会让人白补写一遍 |
| 对账时个别条目回执查不到 | 那几条的远端状态未知 | 该条**不判差异**（不判成「远端没有」），摘要写明「有 N 条未判定」；其余条目照常比对 |
| 登记系统不支持列全部回执 | 查不出「远端有、本地没有」这一类 | 自动降级为按消息控制号逐条查，并在摘要里写明降级原因与未检出的差异类型 |
| 回放时材料已经换过 | 重算结论与落库记录对不上 | 逐条列出差异字段（结论 / 阈值行 / 材料指纹 …）并非零退出；历史那次的判定记录原样保留，**不自动改写** |
| LIS 异常标志与阈值表判定不一致 | 两边说法不同 | 以阈值表为准，留一条口径分歧记录（异常标志只作筛选与交叉校验） |
| 同一标本同一项目同一时刻出现互斥值 | 结论无法唯一确定 | 标「观察歧义」，不自动判定、不出卡 |
| 结果状态为修正（`C`） | 旧结论已过期 | 重新判定，新事件标记取代关系，旧事件置「已被取代」，终态不静默回退 |
| 企微推送失败 | 值班群收不到 | **限流（45009）与网络抖动按指数退避重试**（默认 3 次，基数 0.5 秒、倍数 2、单次封顶 8 秒）；**凭据错 / webhook 非法不重试**（重试一万次也是一样的错）；仍推不出去则落**本机通知记录**并写明失败原因，事件不丢 |
| 值班群被同一个事件刷屏 | 同一条危急值连着推好几遍 | **重复投递抑制**：抑制键 = 事件 ID + 投递状态 + 尝试轮次；同一轮次只允许推一次，第二次**根本没发出去**（`suppressed`），值班台与台账都看得到 |
| 首次推送成功后，到期复查重推被误判成重复 | 值班人没看见的那条永远躺在台账里 | 抑制键带**投递状态**：首次推送是 `initial:1`、到期重推是 `retry:1` / `retry:2`，**各占一把锁，互不抑制** |
| 重试全部失败（推不出去） | 危急值卡在「没人知道」 | **落死信**（原卡内容 + 最后一次错误 + 尝试次数）+ 事件落「处理失败」等人工处理 + 写告警审计；**事件绝不静默丢弃**（仍在台账里）；处置卡正文同时落**本机通知队列**，值班台可见 |
| 推送进程崩在推送中途 | 这条危急值再也推不出去 | 投递轮次停在「在途」；超过陈旧窗口（默认 300 秒）允许重新抢占 —— 宁可重推一次（抑制键兜底，不刷屏），也不让事件卡死 |
| 已被值班人确认的事件又遇推送失败 | 自动路径会不会把既成事实改回失败态 | **不改**：状态迁移只落合法路径，已确认的事件保持「已确认」原样，死信与告警照留（既成事实不可被自动路径改写） |
| 企微返回 HTTP 200 但 `errcode` 非 0 | 以为推成了，其实没推到 | **按失败处理**（企微用 `errcode` 表达成败，不看 HTTP 状态码）；响应不是合法 JSON 同样判失败 |
| 登记系统回写返回 4xx | 契约不匹配 | 落「回写失败」且**不重试**，提示人工改数据；**已确认回执不丢**（确认人 / 确认时刻 / 通知对象 / 上报时限原样留在台账里），可补写 |
| 登记系统回写失败 | 这条回执没能变成已生效事实 | 台账落「回写失败」并写审计；**幂等键仍是消息控制号**，补写时登记系统按同一个键覆盖，**不会生成第二条** |
| 项目紧急度表某一行的权重不是数值 | 那一项排不进优先级 | **只跳过该行**并留告警（写明第几行没采用），其余行照常采用；整张表都不可用时回退内置示例表并告警 —— 一张坏表不会让排序排不出来 |
| 项目紧急度表文件不存在 | 没有院内紧急度口径 | 用内置示例表（零告警）；院内上线按 `samples/urgency.csv.example` 复制到 `data/urgency.csv` 维护 |
| 合并时间窗配了非法值（非数字 / 负数） | 合并边界算不准 | 回落默认 300 秒，告警写明配了非法值 —— 不用一个猜出来的窗口把不同标本并到一张卡 |
| 合并后某一项的依据取不到 | 卡内这一项没有阈值行 | **该项**标「依据缺失」并写明原因，其余项照常显示（不用占位文案冒充已解决）；缺的是整张卡的共享要素（如没有制度条款）时同样标缺项 |
| 登记系统回写返回 5xx 或超时 | 服务端暂时不可用 | 落「回写失败」并留待补写清单；对端恢复后按同一幂等键补写，状态推进到「已回写」 |
| 回写时同一消息控制号内容与既有记录不一致 | 幂等冲突 | 记冲突并转人工，既有事实不被覆盖、不被改写 |
| 值班人迟迟未确认 | 卡片停在待回执 | 按上报时限到期复查重推；重推不重复计数、不覆盖原推送记录，也不被首推抑制 |
| 值班台未配置访问令牌 | 页面可能被越权访问 | 启动自检列出缺失凭据位，给出可执行补齐提示 |
| 入站推送没带或带错 Bearer 凭据 | LIS 推不进来 | 回 `401` 并写审计（只记来源地址与路径，**不记 token 明文**）；服务端没配 `LIS_CRITICAL_TOKEN` 时一律拒绝，不给默认口令 |
| 入站推送请求体超限 | 一次异常大包打满内存 | 回 `413`，**不把 body 读进内存**并断开连接 |
| 入站推送缺必填字段 | 这条结果读不懂 | 回 `422` 并落 `unparsed` 记录 + 写审计；**一条都不静默丢弃**，值班台能看到今天有几条推送没读懂、缺了什么 |
| 入站推送里带了患者标识字段 | 患者信息混进只传结果的通道 | 当场拒绝（`422`）并说明本通道只传结果字段 |
| 同一事件被 LIS 重复推送 | 值班群刷屏、台账长两条 | 幂等键 `event_id + item_code + raised_at`；重复推送回 `200` 带重复标识，不重复判定、不重复出卡、不重复推送，既有事实不被覆盖 |
| LIS 一次 TCP 读带回好几帧（粘包） | 帧边界错位，报文被拼在一起 | 按结束符逐帧切出，**一帧都不少** |
| 一帧被拆成好几次 TCP 读（拆包） | 读到半条报文就当成完整帧 | 读到结束符之前**不交帧**，留在缓冲区等下一次 |
| 收到空帧或帧前垃圾字节 | 这段字节不含报文 | 跳过但留痕（`empty_frame` / `garbage_prefix`），**不静默丢** |
| 连接断开时缓冲区还剩半个帧 | 半个报文被当成完整帧处理 | 记 `incomplete_frame` 留痕，不当报文处理 |
| 单帧超过上限（默认 1 MiB） | 异常大包打满内存 | 丢弃并留痕（`oversized_frame`），重新对齐后续帧，不吞掉后面的报文 |
| 厂商 `OBX-3` 只给中文项目名 | 拿项目名查阈值表必然查不到 | 按阈值表**项目名**匹配到项目码，标低置信「需人工核对」；匹配不上或命中多条 → 转人工，**不把危急值安到别的项目上** |
| LIS 侧 REST 回调返回 4xx | 契约不匹配 | **不重试**（重试也没用），提示人工改数据 |
| LIS 侧 REST 回调返回 5xx / 不可达 | 对端暂时不可用 | 标记为**可重试**，交给上层退避重试 |
| 处置链某一环拿不到该拿的东西 / 交出来的结果形状不对 | 空值顺着链传下去，最后在不相干的地方炸掉 | **当场停在那一环**：该节点与它后面的节点**一个都不跑**，报错带**节点名与字段名**；事件落「转人工」并写审计 `flow_contract_violation`；审计明细写明这一环**能不能重试**（判定这类纯计算环节重跑还是同一个答案 → 不可重试；推送与回写幂等 → 可重试） |
| 链上写错了必填参数 | 配置错了还硬跑 | 立即抛错停住（不改配置就别继续跑），事件仍落转人工并写审计 `flow_param_invalid` |
| 同一个数据目录起了第二个守护进程 | 两套进程各推各的 → 值班群收到两张一样的卡，值班人不知道该按哪一张 | 第二个实例**明确报错退出**（退出码 3）：报出占着目录的进程号、主机与启动时刻；旧实例停机后锁自动释放，可正常再起 |
| 收到停机信号（SIGTERM）时还有事件在队列里 | 危急值已经在队列里了，丢掉就等于漏处置 | **先拒收新事件**（拒收留痕），再在宽限期内把队列排空；宽限期到了还没处理完的**明确留痕**（`daemon_shutdown_abandoned`），不静默消失、不算处理成功 |
| 值班机磁盘被日志吃满 | 台账写不进去、快照存不下，危急值直接进不来 | 日志**按大小滚动**（`CRITVAL_LOG_MAX_BYTES` / `CRITVAL_LOG_BACKUP_COUNT`），旧日志留档不自动清空 |
| 出站依赖（排班系统 / 登记系统 / 企微）连不上 | 处置卡的「通知对象」或回执推不出去 | 健康检查标 `degraded` 并写清哪个依赖不通（**未配置**不算故障）；推送侧另有本机队列兜底，事件不丢 |

## 对接现有系统

### 对接现有系统

本系统的集成面是**四个真实通道**，凭据全部取自环境变量，代码内不出现密钥：

| 方向 | 对端系统 | 协议 | 读写 | 凭据位 |
|------|----------|------|------|--------|
| 入站（主） | LIS 检验系统 | HL7 v2 `ORU^R01` over MLLP（帧以 `\x0b` 起、`\x1c\r` 止） | 读 | 由 MLLP 会话本身承载，无独立凭据 |
| 入站（辅） | LIS 检验系统 | HTTP `POST /api/v1/critical-value-events`（本系统对外提供，LIS 推过来） | 读 | `LIS_CRITICAL_TOKEN`（常量时间比较） |
